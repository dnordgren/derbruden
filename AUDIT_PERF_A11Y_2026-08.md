## How to use this file

Each numbered finding is self-contained. "Fix finding N" must be actionable
with no other context. Each finding states affected files with line numbers,

## Constraints every fix must respect

- Static HTML stays. No frameworks, no client-side rendering, no bundlers.
- NEVER edit `pub/`. It is git-ignored build output. Edit `src/`, then
  `make build`.
- `<!--#include file="partials/x.html" key="value" -->` directives are
  expanded recursively by `scripts/build.mjs`. `{{key}}` inside a partial is
  replaced by the attribute value. Generator output also emits these
  directives; `build.mjs` expands everything before deploy.
- `scripts/generate-stats.js` rewrites the FIRST
  `<div class="table-container">...<table class="stats-table">...</table></div>`
  block in each owner page via regex. Do not rename that wrapper, the
  `stats-table` class, or reorder that table in owner pages.
- `src/drafts.html` and its per-owner "Draft Picks" sections are GENERATED by
  `scripts/generate-drafts.js` (`make drafts`). Page-level styles for the
  draft board live in that script's `pageTemplate()` (~line 355). Edits to
  draft-board markup/CSS must go into the template, then regenerate. If
  `scripts/.env` has a valid `ESPN_S2` cookie, run `make drafts`. If it does
  not, apply the identical edit to both the template and the generated
  `src/drafts.html` / owner sections so the next regeneration does not revert
  the fix. Same relationship for `src/power-rankings.html` and
  `scripts/generate-power-rankings.js` (`make power`).
- Any change to `static/css/site.css` requires bumping `?v=N` in
  `src/partials/head-common.html` (single source; every page gets it through
  the include). `static/` serves with `Cache-Control: max-age=31536000,
  immutable`, so unversioned changes strand returning visitors for a year.
- Run `make build` after HTML/CSS edits and sanity-check `pub/` output.
- New CSS/JS files must pass `npx prettier --check <file>`. Legacy HTML pages
  fail prettier today; do NOT reformat them wholesale. Only touch lines a
  finding requires.
- Relevant tests: `node --test scripts/build.test.mjs
  scripts/generate-drafts.test.mjs`.
- Deploy (Derek only): `AWS_PROFILE=derbruden make deploy`. Wildcard
  CloudFront invalidation (`/*`) is intentional per AGENTS.md; do not narrow
  it.
- Commit style: `feat:` / `fix:` / `chore:` prefixes, imperative mood, Tim
  Pope guidelines.
- Verified live: CloudFront compresses HTML/CSS/JS with brotli. Transfer
  sizes below are brotli unless stated as raw.

## Finding 1 — Draft boards pay full layout/paint cost up front

**Severity:** High. **Area:** Rendering performance on mobile.

### Evidence

- `src/drafts.html` builds 9 season boards in one document: 1,320
  `<div class="pick">` cells plus 1,320 `<td class="board-cell">` wrappers
  (counted via grep). Raw HTML is 210 KB (brotli transfer is fine at 14 KB —
  the cost is client-side layout/paint, not bytes).
- Every owner page carries a "Draft Picks" section with the same dense
  paragraph-per-year markup (e.g. `src/jo.html:209-221`).
- None of these sections are on screen at load, yet the browser lays out and
  paints all of them.

### Fix plan

1. In `static/css/site.css`, add:

   ```css
   .draft-season,
   .draft-history {
     content-visibility: auto;
     contain-intrinsic-size: auto 1200px 800px;
   }
   ```

   `.draft-season` covers each year on drafts.html;
   `.draft-history` covers owner-page sections. Off-screen sections skip
   layout/paint until scrolled near. Anchor jumps (`#draft-2025`) and
   find-in-page still work; the browser renders the target on demand.
2. Bump `site.css?v=1` to `site.css?v=2` in `src/partials/head-common.html:10`.
3. Verify the season-links jump targets land correctly (they may need
   `scroll-margin-top` if anything ever becomes sticky; today nothing is, so
   likely no change).

### Verification

- `make build`, open `pub/drafts.html` in Chrome DevTools Performance panel,
  reload with 4x CPU throttle. First render should show drastically fewer
  layout/paint tasks than before the change; scrolling each season renders
  it on demand with no blank flash longer than a frame or two.
- Click a season link (e.g. `#draft-2018`) from the top: page jumps and the
  board is visible.
- `node --test scripts/build.test.mjs` still passes.

## Finding 2 — dn.html chart overflows phone viewports (fixed 800 px SVG)

**Severity:** High (mobile usability). **Area:** Layout / responsive.

### Evidence

- `src/dn.html:356-358`: the SVG is hardcoded `width=800 height=400`.
- Its container `#chart-container` (`src/dn.html:258`) has no
  `overflow-x` wrapper (unlike every stats table, which sits in
  `.table-container`). Inline style block only sets margins
  (`src/dn.html:36-40`).
- Result: any viewport narrower than ~840 px gets page-wide horizontal
  panning on an otherwise fluid page. This is the only element on the site
  that breaks the 375 px mobile layout.

### Fix plan (pick A; B is acceptable)

**A — responsive SVG (preferred).**
1. In the chart script, replace the fixed width/height with a viewBox and
   let CSS scale it:
   ```js
   const svg = container.append("svg")
     .attr("viewBox", "0 0 800 400")
     .attr("preserveAspectRatio", "xMinYMid meet")
     .style("width", "100%")
     .style("height", "auto");
   ```
   All existing scale math keeps working because it reads
   `svg.attr("width")` — change those reads to the constants
   (`const width = 800 - margin.left - margin.right` etc.) so the layout is
   computed from the viewBox, not a mutated attribute.
2. Text will shrink proportionally on narrow screens. If axis text becomes
   unreadable below ~360 px, wrap the chart in
   `<div class="table-container">...</div>` instead and keep fixed 800 px
   inside the horizontal scroller (that is option B).

**B — scroll wrapper (fallback).**
1. Wrap `<div id="chart-container">` (`src/dn.html:258`) in
   `<div class="table-container">` so the chart pans horizontally inside its
   own box like the tables do.

### Verification

- Open `pub/dn.html` at 375 px and 320 px widths: no horizontal page scroll
  (option A) or a contained chart scroller (option B).
- Bars, both lines, legend, and hover tooltips still render; console clean.

## Finding 3 — dn.html ships the entire D3 bundle for one static chart

**Severity:** High (largest JS payload on the site). **Area:** JavaScript.

### Evidence

- `src/dn.html:277` loads `../static/js/d3.v7.min.js`: 279 KB raw /
  **86 KB brotli**, parsed and executed on every dn.html visit. No other
  page uses it.
- The chart is one team: 10 seasons, band-scaled bars (wins, right axis),
  two line series (points scored/against, left axis), a 3-item legend, and
  hover tooltips. This is ~120 lines of vanilla SVG.
- Bonus bug while you are in there: `src/dn.html:510-512` does
  `chart.selectAll(".line").data(team.data).enter().append("circle")`.
  `selectAll(".line")` matches the TWO already-drawn line paths, so
  `.enter()` yields only **8** of 10 data points — the blue "points scored"
  dots for the first two seasons never render. The red series works because
  its selector (`.line-point-against`) matches nothing initially
  (`src/dn.html:524-528`).

### Fix plan

1. Delete `<script src="../static/js/d3.v7.min.js"></script>`
   (`src/dn.html:277`) and rewrite the inline script (~lines 278-572) with
   plain DOM/SVG:
   - Keep the existing `teamsData` array as-is.
   - Build one `<svg viewBox="0 0 800 400">` (per Finding 2 option A) with
     `<g transform="translate(60,20)">`.
   - Bars: `<rect>` per season, x from band positions
     (`i * step + step*0.25`, `step = plotW / 10`), height from wins on a
     0-14 linear scale, fill `#012f69`.
   - Lines: two `<polyline>` elements with points from 0-2400 scales, stroke
     `#008f00` / `#d60303`, `fill="none"`, `stroke-width="2"`.
   - Axes: bottom baseline line plus season labels (one `<text>` per
     season); left tick labels at 0/800/1600/2400; right tick labels at
     0/7/14. Match the existing `.axis-label` class styles.
   - Legend: reuse the existing pattern — three 10x10 rects + labels at
     `(plotW - 150, -20)`.
   - Tooltips: attach `mouseover`/`mousemove`/`mouseout` on the bars and on
     5 px-radius `<circle>`s for BOTH series (all 10 points each — fixes the
     bug above), driving the existing `#tooltip` div with the same HTML.
2. Remove the dead commented-out export-button block (`src/dn.html:537-568`)
   while rewriting.
3. Merge the duplicate tooltip styling: `#tooltip` has both a CSS rule
   (`src/dn.html:25-34`) and a near-identical inline style attribute
   (`src/dn.html:259-261`). Drop the inline attribute, keep the CSS rule.
4. `git rm static/js/d3.v7.min.js` once dn.html no longer references it (the
   next deploy prunes it from S3 via `--delete`).

If a rewrite is judged too risky, the smaller win is: keep D3 but fix the
circle-binding bug (`selectAll(null)` or a dedicated class for blue points)
and leave the payload. Preferred outcome is the rewrite; the chart is small
and fully specified above.

### Verification

- `pub/dn.html` renders bars, two lines, legend, and tooltips for all 10
  seasons on both series (10 blue + 10 red dots).
- Network tab: no `d3.v7.min.js` request; page JS payload ~0.
- Console clean; `grep -rn "d3.v7" src/ scripts/*.js` returns nothing.

## Finding 4 — Nav semantics, skip link, tap targets

**Severity:** High. **Area:** Accessibility / mobile input.

### Evidence

- `src/partials/nav.html` is a single `<p>` with literal `||` text between
  links. Screen readers may announce the pipe characters (verbosity-dependent)
  and the group is not exposed as a navigation list. There is no way to skip
  past header + sponsor + nav to main content on every page.
- Tap targets are bare 16 px text links with `line-height: 1.6` (~26 px hit
  height). WCAG 2.5.8 wants >=24 px; iOS HIG wants ~44 px. Seven links packed
  with `||` also wrap unpredictably at 320 px.

### Fix plan

1. Rewrite `src/partials/nav.html` as a semantic list:

   ```html
   <nav aria-label="Main">
     <ul>
       <li><a href="./about.html">About</a></li>
       <li><a href="./owners.html">League Owners</a></li>
       <li><a href="./power-rankings.html">Power Rankings</a></li>
       <li><a href="./records.html">Records</a></li>
       <li><a href="./trades.html">Trades</a></li>
       <li><a href="./drafts.html">Drafts</a></li>
       <li><a href="./waivers.html">Waivers</a></li>
     </ul>
   </nav>
   ```

2. Style it in `static/css/site.css` (replacing the `nav ul/li` rules at
   lines 78-85):

   ```css
   nav ul {
     list-style: none;
     padding: 0;
     margin: 0;
     display: flex;
     flex-wrap: wrap;
     gap: 4px 18px;
   }

   nav a {
     display: inline-block;
     padding: 10px 2px;
   }
   ```

   The padding lifts tap height to ~41 px without changing the visual look
   much; increase to `padding: 12px 2px` if you want the full 44 px.
3. Add a skip link as the first element inside `<body>` of
   `src/partials/site-header.html` (so every page inherits it):

   ```html
   <a class="skip-link" href="#main">Skip to content</a>
   ```

   …and add `id="main"` to the `<main>` element on every page (16 pages in
   `src/`, plus the `<main>` in `generate-drafts.js` and
   `generate-power-rankings.js` templates). CSS:

   ```css
   .skip-link {
     position: absolute;
     left: -9999px;
     top: 0;
     background: #fff;
     padding: 10px 16px;
     z-index: 10;
   }

   .skip-link:focus {
     left: 8px;
     top: 8px;
   }
   ```

4. Optional, cheap: the include mechanism supports `{{key}}` substitution.
   Change nav links to `<a href="./about.html" aria-current="{{cur_about}}">`
   etc., then pass e.g. `cur_about="page"` only from `about.html`'s include
   (`<!--#include file="partials/nav.html" cur_about="page" -->`). Pages
   that omit a key render an empty attribute value, which is harmless, but
   cleaner: emit `aria-current="{{cur_x}}"` only where set — if the build
   leaves `aria-current=""` behind, strip empty attributes by post-processing
   or just skip this step. Do it only if trivially clean; it is not required.

### Verification

- VoiceOver/TalkBack on a phone: nav announces as "navigation list, 5
  items"; pipes are gone; skip link appears first and jumps to content.
- 320 px viewport: nav wraps into tidy rows; each link's tap rect >=40 px
  tall (DevTools inspector).
- `make build`; spot-check `pub/index.html`, `pub/trades.html`, one owner
  page for the expanded list + skip link + `id="main"`.

## Finding 5 — Content links are invisible as links on touch

**Severity:** High. **Area:** Accessibility (WCAG 1.4.1) / mobile UX.

### Evidence

- `static/css/site.css:105-112`: `a { color: #000; text-decoration: none }`
  with underline on hover only. Touch devices have no hover.
- Affected link groups: the entire nav, championship winner/runner-up links
  on `src/index.html:42-68` etc., leadership/excommunicado links on
  `src/about.html:47-53`, owner links in power-rankings rows.
- Table links are fine: `.stats-table td a` is `#00429f` + underline
  (`site.css:152-155`), and `.season-links a` on drafts is underlined.

### Fix plan

1. In `static/css/site.css`, make in-content links self-evident without
   relying on hover:

   ```css
   main a:not(.stats-table td a) {
     text-decoration: underline;
     text-underline-offset: 2px;
   }
   ```

   Simpler alternative if the `:not` chain feels fragile: change the global
   rule to `a { color: #000; text-decoration: underline }` and explicitly
   disable underline only where it hurts (`.season-links a` already sets its
   own; add `text-decoration: none` to `nav a` if you want the nav clean,
   since nav position + tap padding already signals clickability).
2. Bump `site.css?v=2` (or next N) in `src/partials/head-common.html:10`.

Pick ONE convention sitewide: either "underlined everywhere except nav" or
"underlined in main content only". Do not leave hover as the only signal
anywhere.

### Verification

- On a phone (or DevTools touch emulation), every tappable text link on
  index/about/power-rankings/nav is distinguishable from plain text without
  hovering.
- No double-underline weirdness where `.stats-table td a` already underlines.

## Finding 8 — Table semantics and the orphaned `.totals-row`

**Severity:** Medium. **Area:** Accessibility.

### Evidence

- Zero `scope` attributes and zero `<caption>` elements sitewide (grep:
  0 results). Screen readers can still associate cells heuristically, but
  explicit `scope` makes complex tables (11-column stats, 11-column draft
  boards) reliable.
- `tr class="totals-row"` appears in all 10 owner pages (e.g.
  `src/jo.html:194`) but NO CSS rule for it exists anywhere (grep across
  `src/`, `static/css/`, `scripts/`). The totals row renders identical to
  data rows — presumably unintended.
- Championship columns encode data as emoji: `🏆` / `🏆🏆🏆` / empty cell
  (`src/owners.html:59,83,107`...). Screen readers hear "trophy trophy
  trophy" or silence; the count is the actual datum.
- Sort arrows in headers imply sortable tables that are not sortable:
  "Win % | ↓" (`src/owners.html:28`), "Rating | ↓"
  (`src/power-rankings.html:62`). Cosmetic confusion, not an a11y failure.

### Fix plan

1. Add `scope="col"` to every header `<th>` in: `src/owners.html:24-33`,
   the stats tables in all 10 owner pages, `src/power-rankings.html:54-63`,
   `src/trades.html:124-126`, and the draft-board headers in
   `scripts/generate-drafts.js` template (+ generated `src/drafts.html`).
   Add `scope="row"` to the leading `th.round-head` cells of each draft
   board row and to the season `td` if converted — draft boards use
   `th.round-head` per row already; give them `scope="row"`.
   NOTE: `generate-stats.js` regenerates owner stat tables — check whether
   it emits `<th>` headers and add `scope` there too if so, otherwise the
   next stats run strips them. If adding scope in generator output is
   awkward, skip owner stat tables and do the rest.
2. Captions: add a visually-hidden `<caption>` as the first child of each
   stats table using the `.visually-hidden` class from Finding 7 — e.g.
   "Season-by-season record, JO", "League totals, all owners",
   "2026 Elo power rankings", "Trade log". For draft boards:
   "2025 draft board". Owner stat tables get rewritten by
   `generate-stats.js` — if it stomps captions, extend that script's
   template string instead of fighting it.
3. Totals row: add to `static/css/site.css`:

   ```css
   .totals-row td {
     border-top: 2px solid #ddd;
     font-weight: 700;
   }
   ```

   Bump `?v=N`.
4. Trophy cells: replace emoji counts with numerals plus a screen-reader
   label, e.g. `<td class="number"><span aria-hidden="true">🏆🏆🏆</span>
   <span class="visually-hidden">3 championships</span></td>` and
   `<span class="visually-hidden">0</span>` for empties. Only
   `src/owners.html` needs this (12 occurrences). Alternatively simply
   print the digits ("3") — simpler and arguably clearer; Derek's call on
   aesthetics.
5. Leave the fake sort arrows alone OR delete them; if deleted, touch
   `src/owners.html:28` and the power-rankings generator template
   (`scripts/generate-power-rankings.js` emits "Rating | &darr;").

### Verification

- VoiceOver swipe through one owners-table row: hears column headers on

## Finding 11 — Google Fonts: render-blocking third-party chain

**Severity:** Medium. **Area:** Font loading / first paint.

### Evidence

- `src/partials/head-common.html:4-9`: preconnects + a render-blocking
  stylesheet to `fonts.googleapis.com`, requesting Archivo
  `ital,wght@0,400;0,500;0,600;0,700;1,400`. First visit pays:
  DNS+TLS to googleapis, CSS fetch, then font fetches from gstatic before
  swap completes. Site already self-hosts everything else.
- Weights actually used: 400 (body), 500 (`.stats-table .owner`),
  600 (badges, board heads), 700 (strong, pick names), italic 400 (em).

### Fix plan (option A preferred; B is the cheap version)

**A — self-host the five variants.**

1. Download woff2 latin subsets (Google serves different formats by UA; send
   a modern Chrome UA):

   ```sh
   mkdir -p static/fonts
   curl -s -A "Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126 Safari/537.36" \
     "https://fonts.googleapis.com/css2?family=Archivo:ital,wght@0,400;0,500;0,600;0,700;1,400&display=swap" \
     -o /tmp/opencode/archivo.css
   # Extract the latin-subset woff2 URLs (last src per @font-face block whose
   # unicode-range covers U+0000-00FF) and download five files:
   # archivo-400.woff2 archivo-500.woff2 archivo-600.woff2 archivo-700.woff2 archivo-400italic.woff2
   ```

2. Replace the Google links in `src/partials/head-common.html` with
   preloads (crossorigin is REQUIRED even for same-origin fonts):

   ```html
   <link rel="preload" href="../static/fonts/archivo-400.woff2" as="font" type="font/woff2" crossorigin />
   <link rel="preload" href="../static/fonts/archivo-700.woff2" as="font" type="font/woff2" crossorigin />
   ```

   (Preload just 400 + 700; the others load on demand via CSS.)
3. Add `@font-face` rules to the TOP of `static/css/site.css`:

   ```css
   @font-face {
     font-family: 'Archivo';
     font-style: normal;
     font-weight: 400;
     font-display: swap;
     src: url('../fonts/archivo-400.woff2') format('woff2');
   }
   /* repeat for 500, 600, 700, and italic 400 */
   ```

   The existing `font-family: 'Archivo', 'Helvetica Neue', Arial, sans-serif`
   stack (`site.css:6`) keeps working.
4. Delete the `preconnect` hints and the Google stylesheet link.
5. Bump `site.css?v=N`.

Win: removes two third-party origins and the render-blocking CSS fetch;
fonts become immutable-cached first-party assets; 400/700 start downloading
immediately via preload.

**B — stay on Google, trim the request.**
Change the URL to `family=Archivo:ital,wght@0,400;0,700;1,400` and remap the
few `font-weight: 500/600` declarations to 400/700 respectively (visual
delta is small: `.stats-table .owner`, `.event-badge`, `.round-head`,
`.team-head`). Fewer font files, still third-party.

### Verification

- Network waterfall on a cold load: no fonts.googleapis/fonts.gstatic
  requests (option A); woff2 files arrive from derbruden.com with
  `immutable` caching; text renders with correct weights (spot-check bold
  headlines, italic tagline, medium owner cells).
- Repeat visit: fonts served from disk cache.
